# zpg: руководство пользователя

zpg позволяет смотреть и править таблицы PostgreSQL прямо в Zed. Таблица открывается как обычный текстовый файл. Правите ячейки как текст, сохраняете файл и применяете изменения, после чего они записываются в базу.

## Установка

1. Соберите и установите бинарник (он работает и как CLI, и как language server):

   ```sh
   cargo install --path crates/zpg
   ```

   Он попадёт в `~/.cargo/bin/zpg`. Эта папка должна быть в `PATH`, который видит Zed.

2. В Zed: `ctrl-shift-p` → **zed: install dev extension** → выберите папку репозитория zpg.

3. Добавьте задачу для открытия каталога в `~/.config/zed/tasks.json`:

   ```json
   {
     "label": "zpg: open catalog",
     "command": "zpg",
     "args": ["open", "$ZED_WORKTREE_ROOT"],
     "reveal": "never",
     "hide": "on_success"
   }
   ```

   `zpg open [путь к проекту]` создаёт `.zpg/catalog.pgdb` (если его ещё нет) и открывает его командой `zed`. Другой CLI Zed можно указать через `--zed` или переменную `ZPG_ZED`.

   При желании повесьте её на хоткей в `~/.config/zed/keymap.json`:

   ```json
   { "context": "Workspace",
     "bindings": { "ctrl-alt-q": ["task::Spawn", { "task_name": "zpg: open catalog" }] } }
   ```

4. Для запуска SQL из `.sql`-файлов установите расширение Zed **SQL** (`zed: extensions` → SQL). Оно даёт язык SQL, к которому подключается zpg. Code lens («▶ Run») должны быть включены: `"code_lens": "on"` в `settings.json`.

5. Включите подсветку изменённых ячеек: в Zed она выключена по умолчанию. Добавьте в `~/.config/zed/settings.json`:

   ```json
   "languages": {
     "Pg Table": { "semantic_tokens": "combined" },
     "Pg Row": { "semantic_tokens": "combined" }
   }
   ```

После обновления бинарника (`cargo install` заново) перезапустите сервер: `ctrl-shift-p` → **editor: restart language server**. После изменения грамматики или подсветки в репозитории: **zed: rebuild dev extension**.

## Подключения

Все настройки zpg лежат в одном файле пользователя — `~/.config/zpg/config.json`, общем для всех проектов. Файл вне проектов, поэтому пароли не попадут в git. `.zed/settings.json` zpg не читает.

Файл создаётся сам с примерами в комментариях при первом запуске zpg. Открыть его:

- в каталоге: `ctrl-.` → **zpg: Open settings file**;
- из терминала: `zpg config`.

```jsonc
{
  "connections": {
    "local": "postgresql:///mydb?host=/var/run/postgresql",
    "stage": "postgresql://app:secret@stage-db:5432/app",
    "prod": { "url": "postgresql://app:secret@prod-db/app", "read_only": true },
  },
  "page_size": 100,
  "max_cell_width": 40,
  "apply": "manual",
}
```

- Можно писать комментарии `//` и `/* */` и оставлять запятую после последнего элемента, как в настройках Zed.
- Сохранённые изменения применяются при следующем действии в zpg (каталог, таблица, `.sql`), перезапускать ничего не нужно. Открытый каталог обновится сам.
- Права на файл — `600` (читает только владелец). Другой путь можно задать переменной `ZPG_CONFIG`; по умолчанию учитывается `XDG_CONFIG_HOME`, на Windows файл лежит в `%APPDATA%\zpg\config.json`.

### Параметры

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `connections` | — | Имя подключения → строка подключения, или объект `{ "url": ..., "read_only": true }` |
| `page_size` | `100` | Сколько строк загружать на страницу |
| `max_cell_width` | `40` | Ширина, после которой значение обрезается до `…` |
| `apply` | `"manual"` | Режим для вновь открываемых таблиц: `manual` или `save` (см. [Сохранение](#сохранение-в-базу)) |
| `max_result_rows` | `1000` | Сколько строк результата показывать при запуске SQL |
| `statement_timeout_ms` | `60000` | Таймаут одного запуска SQL в миллисекундах, `0` — без таймаута |

### Строка подключения

Подходят оба формата libpq:

| Случай | Пример |
|---|---|
| Локально через unix-сокет | `postgresql:///mydb?host=/var/run/postgresql` |
| То же, формат key=value | `host=/var/run/postgresql dbname=mydb` |
| По сети | `postgresql://user:password@host:5432/mydb` |
| Без TLS | `postgresql://user@host/mydb?sslmode=disable` |

- Если пользователь не указан, берётся `$USER`.
- **Пароли** можно писать прямо в URL: файл настроек лежит вне проектов. Если хочется держать пароль в переменной окружения, работает `${VAR}`: значение берётся из окружения проекта (direnv или окружение, из которого запущен Zed).
- **TLS.** `sslmode=prefer` (по умолчанию) и `require` шифруют соединение без проверки сертификата, как libpq. `verify-ca` и `verify-full` не поддерживаются.
- **`read_only: true`** делает все таблицы подключения доступными только для чтения. Транзакции тоже открываются read-only. Включите это для боевых баз.

### Через SSH

Если база доступна только с сервера, добавьте в подключение `ssh`. zpg сам поднимет туннель через системный `ssh` и закроет его при выходе:

```json
"prod": {
  "url": "postgresql:///app?host=/var/run/postgresql",
  "ssh": "deploy@prod.example.com",
  "read_only": true
},
"stage": {
  "url": "postgresql://app:${STAGE_PG_PASSWORD}@10.0.0.5:5432/app",
  "ssh": "stage-bastion",
  "ssh_options": ["-p", "2222"]
}
```

- **`url`** задаёт базу так, как её видит сервер. Например, `host=/var/run/postgresql` — unix-сокет Postgres на сервере. Тогда работает peer-аутентификация от имени SSH-пользователя, и пароль БД не нужен. Адрес вида `10.0.0.5:5432` — база во внутренней сети сервера.
- **`ssh`** — `user@host` или имя хоста из `~/.ssh/config`. Ключи, ssh-agent, `ProxyJump` через бастион и порт берутся оттуда же.
- **`ssh_options`** — дополнительные аргументы `ssh`, если не хочется трогать `~/.ssh/config`.
- **Только вход по ключу или через agent.** Пароль SSH zpg спросить не сможет. Сервер должен быть уже в `known_hosts`: один раз зайдите на него `ssh deploy@prod.example.com` из терминала.
- **Если туннель упал** (сеть, сон ноутбука), следующий запрос поднимет его заново.
- **Ошибки ssh** (`Permission denied`, `Host key verification failed`, не найден хост) видны в каталоге под именем подключения.

## Быстрый старт

1. Пропишите подключение в `~/.config/zpg/config.json` (см. выше).
2. `ctrl-shift-p` → **task: spawn** → **zpg: open catalog**. Откроется `.zpg/catalog.pgdb` со списком таблиц.
3. Поставьте курсор на имя таблицы и нажмите **F12** (go to definition). Откроется первая страница таблицы.
4. Исправьте значение в ячейке и сохраните файл (`ctrl-s`). На первой строке появится `pending: 1 update`.
5. `ctrl-.` → **zpg: Apply changes**. Изменение записано в базу.

## Каталог

```
# zpg v1 catalog
# Go to definition (F12) on a table opens it; code actions refresh.

[local]
public.audit_log         table       ~84000 rows
public.sessions          table       ~1200 rows
public.users             table       ~350 rows
public.v_active_users    view

[prod]
! password authentication failed for user "app"
```

- `[имя]` — подключение из настроек. Под ним таблицы, view, materialized view и foreign tables, на которые у пользователя есть право SELECT.
- `~N rows` — оценка планировщика (`reltuples`). У таблиц, которые ещё ни разу не анализировались, её нет.
- `! ...` — ошибка подключения. Исправьте настройки, каталог обновится сам.
- **F12** на строке таблицы открывает её. Если таблица уже открывалась, откроется существующий файл со всеми незаписанными правками. Свежие данные загружает [Refresh](#code-actions).
- `ctrl-.` → **zpg: Refresh catalog** перечитывает список таблиц. После `CREATE`/`DROP`/`ALTER`, запущенных из `.sql`, каталог обновляется сам.
- **Удаление таблицы.** `ctrl-.` на строке таблицы → **zpg: Drop public.users…** открывает файл `.zpg/<подключение>/drop-public.users.sql` с готовым запросом. Тип объекта подставляется сам: `DROP TABLE`, `DROP VIEW`, `DROP MATERIALIZED VIEW` или `DROP FOREIGN TABLE`. Проверьте запрос и нажмите ▶, только тогда таблица будет удалена. Чтобы удалить и зависимые объекты (view, внешние ключи), допишите `CASCADE`.

## Страница таблицы

```
# zpg v1 conn=local table=public.orders pk=id page=1 limit=100 width=40 apply=manual
| id | user_id | status  | payload                        | comment            |
|----|---------|---------|--------------------------------|--------------------|
| 1  | 2       | paid    | {"items": [1, 2], "total": 10} | line one\nline two |
| 2  | 1       | new     | NULL                           | NULL               |
```

- **Строка 1, шапка.** Параметры страницы, см. [Шапка](#шапка-фильтр-сортировка-страницы).
- **Строка 2, имена колонок.** Менять нельзя.
- **Строка 3, разделитель.** Его выравнивание обновляется автоматически.
- **Дальше идут строки данных.** Значения показаны в текстовом виде Postgres: `true`/`false`, даты `2026-10-16 12:00:00+05`, JSON как есть, массивы `{1,2,3}`.

**Широкие таблицы.** Zed всегда переносит строки длиннее 512 символов, независимо от настроек (`soft_wrap`). Поэтому zpg держит строку таблицы короче 500 символов: если колонки не помещаются, самые широкие из них обрезаются до общей ширины. Ключевые колонки не обрезаются никогда. Если таблица не помещается даже так, на строке с именами колонок появится подсказка. Тогда выберите нужные колонки через [`columns=`](#шапка-фильтр-сортировка-страницы).

**Подсветка.** Числа, `true`/`false`, `NULL`/`DEFAULT` и обрезанные значения выделяются цветом. В каталоге выделяются подключения, имена и типы таблиц и ошибки, в просмотре строки — имена полей и блоки текста. Если включены semantic tokens (см. [Установка](#установка)), ещё до записи в базу видно, что изменится: изменённые ячейки и новые строки подчёркнуты.

**Наведите курсор на ячейку** (hover): появятся имя колонки, её тип, признаки `primary key`, `not null`, `has default`, `generated` и внешний ключ. Для обрезанного значения (`…`) там же показано полное значение, а для некоторых типов — больше, чем помещается в ячейку:

| Тип | Что показывает hover |
|---|---|
| `json`, `jsonb` | отформатированный JSON с подсветкой (если значение обрезано) |
| `timestamptz` | день недели, «3 hours ago» / «in 2 days», время в UTC и в вашем часовом поясе |
| `timestamp` | день недели и «сколько прошло» в двух вариантах: если время записано в вашем поясе и если в UTC |
| `date` | день недели, «today», «tomorrow», «5 days ago» |
| `integer`, `bigint` из 10 или 13 цифр | дату, если это Unix-время в секундах или миллисекундах (2001–2100) |
| массивы | элементы по одному в строке: `[1] a`, `[2] b`, для многомерных `[1][2]` |
| `xml` | с отступами и подсветкой |
| `bytea` | размер; текст, если это UTF-8, иначе hex-дамп первых 256 байт |

Значения длиннее 20 000 символов в hover обрезаются, целиком их показывает просмотр строки. На ячейке внешнего ключа показана строка, на которую он ссылается.

## Редактирование

### Изменить значение
Просто перепечатайте текст ячейки. Ширину колонок выравнивать не нужно: при сохранении таблица выровняется сама.

### Добавить строку
- Удобнее всего так: `ctrl-.` → **zpg: Insert row**. Под курсором появится заготовка, в которой уже подставлены `+` для ключа, `DEFAULT` для колонок со значением по умолчанию и `NULL` для необязательных. Заполните остальное.
- Можно и вручную: допишите строку, а в ключевой колонке поставьте `+`, тогда ключ возьмётся из sequence или identity.
- Строка с ключом, которого нет на странице, тоже считается новой. Так удобно скопировать строку (`ctrl-alt-shift-down`) и поменять ключ.

### Удалить строку
Удалите строку из файла целиком.

### Специальные значения

| Пишете | В базу уйдёт |
|---|---|
| `NULL` | NULL |
| `DEFAULT` | значение по умолчанию колонки |
| `+` (только в ключевой колонке) | новая строка, ключ по умолчанию |
| пустая ячейка | пустая строка `''` |
| `\NULL`, `\DEFAULT`, `\+` | текст `NULL`, `DEFAULT`, `+` |

### Экранирование внутри значения

| Пишете | Означает |
|---|---|
| `\\|` | символ `\|` (иначе это граница ячейки) |
| `\\` | обратный слэш |
| `\n`, `\t`, `\r` | перевод строки, табуляция, возврат каретки |
| `\s` | пробел в начале или конце значения (пробелы по краям ячейки обрезаются) |

Длинный текст и JSON удобнее править в [просмотре строки](#просмотр-строки): там переводы строк выглядят как обычные строки, а JSON отформатирован.

### Что нельзя править
- **Обрезанные значения (`…`).** zpg не знает, что вы имели в виду. Откройте [просмотр строки](#просмотр-строки), увеличьте `width` в шапке (`width=0` отключает обрезку) или оставьте меньше колонок через `columns=`, чтобы zpg не пришлось их сужать.
- **Ключ существующей строки.** Изменение ключа считается удалением старой строки и вставкой новой. Это сработает, но учтите внешние ключи с `ON DELETE CASCADE`.
- **Generated-колонки.** В них допустим только `DEFAULT`.
- **Таблицы без первичного ключа, view и materialized view.** Они только для чтения. Ключевые колонки никогда не обрезаются: по ним zpg находит строку в базе.

## Сохранение в базу

Пока вы правите, на первой строке висит подсказка с тем, что будет записано: `pending: 1 update, 1 insert, 1 delete`. Ошибки подчёркиваются сразу, ещё до сохранения: неверное число ячеек, дубль ключа, правка обрезанного значения и т. п.

Все изменения страницы записываются **одной транзакцией**:
- изменённые ячейки → `UPDATE` (только изменённые колонки);
- новые строки → `INSERT`;
- удалённые строки → `DELETE`.

После успеха страница перерисовывается с данными из базы: появляются новые id, подставленные `DEFAULT` и т. п. Внизу всплывёт `zpg: saved 1 update, 1 insert`.

### Режим `apply=manual` (по умолчанию)
`ctrl-s` только сохраняет файл, в базу ничего не уходит. Записать изменения: `ctrl-.` → **zpg: Apply changes**. Так случайно стёртая строка или опечатка не попадут в базу, а перед записью можно посмотреть **Preview SQL**.

### Режим `apply=save`
Каждое `ctrl-s` сразу записывает изменения в базу. Удобно для быстрой правки, но **отменить записанное через `ctrl-z` нельзя**. Для баз с важными данными оставляйте `manual`.

Переключить режим: поменяйте `apply=` в шапке, или `ctrl-.` → **zpg: Apply changes manually / on save**, или `"apply"` в настройках (для вновь открываемых таблиц).

### Посмотреть SQL до записи
`ctrl-.` → **zpg: Preview SQL** откроет файл с SQL, который выполнится:

```sql
BEGIN;
UPDATE "public"."users" SET "name" = CAST('Anya' AS text) WHERE "id" = CAST('1' AS integer) AND xmin = CAST('7421' AS xid) RETURNING ...;
COMMIT;
```

### Если что-то пошло не так
Если хоть один запрос упал, транзакция откатывается и **в базу не записывается ничего**. Ошибка Postgres показывается на строке, которая её вызвала. Правки остаются в файле: исправьте и примените снова.

### Защита от чужих изменений
Каждый `UPDATE`/`DELETE` проверяет, что строка не менялась с момента загрузки (по системной колонке `xmin`). Если её успел изменить кто-то другой, запись отменяется с ошибкой «row was changed or deleted since it was loaded». Сделайте **Refresh**, чтобы увидеть актуальные данные, и внесите правку заново.

## Связанные таблицы и просмотр строки

### Переход по внешнему ключу
**F12** (или `ctrl`+клик) на ячейке внешнего ключа открывает связанную таблицу, отфильтрованную по этому значению: в шапке будет `where="id = '2'"`. Чтобы снова увидеть всю таблицу, удалите `where` из шапки и сохраните. Если в связанной таблице есть незаписанные правки, она откроется как есть, без фильтра.

### Просмотр строки
**F12** на ячейке первичного ключа (или `ctrl-.` → **zpg: Open row**) открывает строку вертикально, по полю на строку текста:

```
# zpg v1 row conn=local table=public.orders key=id=1
id: 1
user_id: 2
status: paid
payload: |
  {
      "items": [
          1,
          2
      ],
      "total": 10
  }
comment: |
  line one
  line two
```

- Значение с переводами строк записывается блоком: `имя: |`, затем строки с отступом в два пробела. Добавляйте и удаляйте строки внутри блока как обычный текст.
- `jsonb` показывается отформатированным (`jsonb_pretty`). В базу уходит как есть, Postgres сам его разберёт.
- Однострочные значения пишутся так же, как в таблице: `NULL`, `DEFAULT`, экранирование `\n` и т. п. `имя:` без значения означает пустую строку.
- Ключевые поля менять нельзя. Порядок и состав полей тоже.
- Изменённые поля подчёркиваются так же, как ячейки в таблице, а на первой строке появляется `pending: 1 update`.
- Строка записывается по тем же правилам, что и таблица. В режиме `manual` это `ctrl-.` → **zpg: Apply changes**, в режиме `save` — `ctrl-s`. Режим берётся из таблицы, из которой открыта строка.
- После записи страница таблицы тоже обновляется, если в ней нет своих незаписанных правок.
- Hover и F12 по внешнему ключу работают и здесь.
- Повторный F12 на том же ключе перечитывает строку из базы. Исключение: если в `.pgr` есть правки, ещё не записанные в базу (сохранённые в файле или нет), он просто откроется как есть, правки не пропадут. Перечитать вручную: `ctrl-.` → **zpg: Refresh row**.

## Автодополнение

`ctrl-space` (или просто начните печатать):

| Где | Что предлагается |
|---|---|
| ячейка или поле строки | `NULL` (если колонка допускает), `DEFAULT` (если есть значение по умолчанию), `+` в ключе, `true`/`false` для boolean, значения enum |
| шапка, внутри `where="…"` | имена колонок, `and`, `or`, `is null`, `like`… |
| шапка, внутри `order="…"` | имена колонок, `asc`, `desc`, `nulls last`… |
| шапка, внутри `columns="…"` | имена колонок |
| шапка, вне значений | поля `where`, `order`, `columns`, `page`, `limit`, `width`, `apply` |

## Выполнение SQL из .sql-файлов

Откройте любой `.sql`-файл проекта. Над каждым запросом появится кнопка **▶ Run on local** (code lens). Нажмите её, и запрос выполнится.

```sql
-- @conn local
select id, name, email from users where active order by id;

update users set active = false where id = 42;
```

### Подключение
- Строка `-- @conn имя` задаёт подключение для всех запросов ниже неё, до следующей такой строки. В одном файле можно чередовать базы.
- Без `-- @conn`, если подключение в настройках одно, используется оно. Если подключений несколько, над запросом будет по кнопке на каждое: «▶ local», «▶ prod».

### Как запускать
- **Кнопка над запросом** выполняет этот запрос.
- **`ctrl-.` на запросе** → **zpg: Run statement on …** — то же самое без мыши.
- **Выделите несколько запросов** → `ctrl-.` → **zpg: Run selection on …**. Они выполнятся по очереди в одной транзакции. Если упадёт любой из них, откатятся все.
- Запросы разделяются `;`. Точки с запятой внутри строк, `$$`-тел функций и комментариев не считаются. Данные после `COPY … FROM stdin;` в дампах `pg_dump` пропускаются до строки `\.`.
- Если нажать ▶ сразу после правки, пока Zed не перерисовал кнопки, zpg сам найдёт нужный запрос: по его тексту или, если вы правили сам запрос, по месту, где он начинается. Если ни то ни другое не подходит, ничего не выполнится, и zpg попросит нажать снова.
- В файлах больше 5 МБ (например, полные дампы) кнопок ▶ нет, запускайте через `ctrl-.`.

### Что получается
- **Запрос возвращает строки** (`SELECT`, `… RETURNING`). Результат откроется вкладкой `.pgres` в табличном виде. Повторный запуск из того же `.sql` обновит ту же вкладку. Показываются первые `max_result_rows` строк, остальные не выбираются из базы вовсе.
- **Запрос не возвращает строк** (`UPDATE`, `INSERT`, DDL). Внизу всплывёт итог вида `zpg: UPDATE 3 (4 ms)`.
- **Ошибка.** Всё откатывается, ошибка подчёркивается в `.sql` прямо в месте, на которое указал Postgres (например, на имени несуществующей колонки), а в сообщении есть подсказка Postgres.
- Запуск идёт в транзакции с `statement_timeout`. Для подключений с `read_only: true` транзакция только на чтение.
- `VACUUM`, `CREATE INDEX CONCURRENTLY` и другие команды, которые не работают внутри транзакции, при запуске поодиночке выполняются без неё.

### Подсказки по таблицам и колонкам
zpg знает таблицы и колонки подключения, на котором выполняется запрос (по `-- @conn`; если подключений несколько и строки нет — первого по алфавиту).
- **Автодополнение.** После `from`, `join`, `update`, `into` предлагаются таблицы и схемы. После `u.`, где `u` — алиас или имя таблицы из запроса, предлагаются её колонки, после `схема.` — таблицы схемы. В остальных местах предлагаются колонки таблиц запроса, таблицы и ключевые слова. Таблицы схемы `public` пишутся без схемы.
- **Hover** на таблице показывает её колонки с типами, на колонке — тип и признаки (`not null`, `has default`).
- **`F12`** на таблице или колонке открывает страницу таблицы.
- Список таблиц читается из базы при первой подсказке и хранится 5 минут. DDL, выполненный из `.sql`, и **Refresh catalog** обновляют его сразу.

### Вкладка результата (.pgres)
```
# zpg v1 result conn=local rows=2 time=4ms
# select id, name, email from users where active order by id
# Rows of public.users: code action “Edit rows in table” opens them for editing.
| id | name | email            |
|----|------|------------------|
| 1  | Anna | anna@example.com |
| 2  | Bob  | NULL             |
```
- Результат только для чтения. Hover показывает тип колонки и полное значение обрезанной ячейки.
- `ctrl-.` → **zpg: Run again** (или **Refresh**) перезапускает запрос.
- `ctrl-.` → **zpg: Edit rows in table**. Доступно, если все колонки результата взяты из одной таблицы и среди них есть её первичный ключ. Откроется обычная страница этой таблицы, отфильтрованная вашим запросом: `where="id IN (SELECT id FROM (ваш запрос) AS zpg_q)"` и `columns=` по выбранным колонкам. Дальше правка идёт как обычно. Сортировка страницы — по ключу, при желании поменяйте `order=`.

## Шапка: фильтр, сортировка, страницы

Первая строка управляет тем, какие строки показаны. Поменяйте её и нажмите `ctrl-s`, страница загрузится заново.

```
# zpg v1 conn=local table=public.audit_log pk=id page=1 limit=200 width=60 apply=manual where="level = 'error'" order="id desc" columns="created_at, level, message"
```

| Поле | Что делает | Пример |
|---|---|---|
| `page` | номер страницы | `page=3` |
| `limit` | строк на странице, до 10 000 | `limit=500` |
| `where` | SQL-условие фильтра | `where="created_at > now() - interval '1 day'"` |
| `order` | SQL-сортировка; по умолчанию по ключу | `order="created_at desc, id"` |
| `columns` | какие колонки показывать, через запятую; без поля — все | `columns="name, email, phone"` |
| `width` | ширина обрезки значений, `0` = не обрезать | `width=0` |
| `apply` | `manual` или `save` | `apply=save` |
| `conn`, `table`, `pk` | только для информации, менять нельзя | |

- `where`, `order` и `columns` можно писать без кавычек: значение тянется до следующего поля шапки. `order=id desc` и `where=active and id > 5` работают как есть, при сохранении zpg сам возьмёт их в кавычки. Остальные значения с пробелами пишутся в двойных кавычках, кавычка внутри — `\"`. Одинарные кавычки SQL пишутся как есть.
- **Сортировка без правки шапки:** курсор на имени колонки в строке заголовков → `ctrl-.` → **zpg: Sort by name ↑** (по возрастанию) или **↓** (по убыванию). Страница сразу перезагрузится с первой страницы.
- **`columns`.**
  - Ключевые колонки показываются всегда, даже если их нет в списке.
  - Колонки идут в порядке таблицы, а не списка.
  - Скрытые колонки при записи не трогаются. В новых строках они получают значение по умолчанию.
  - Если скрыта обязательная колонка (NOT NULL без значения по умолчанию), новая строка подсветится ошибкой «a new row needs …». Добавьте эту колонку в список.
  - `columns` и `width` только перерисовывают уже загруженные строки, база при этом не читается.
- Чтобы убрать фильтр или сортировку, удалите поле целиком.
- В режиме `manual` страница со смененной шапкой перезагрузится, только если нет незаписанных правок: сначала примените или отмените их. В режиме `save` правки сначала запишутся, потом загрузится новая страница.
- Ошибка в `where`/`order` придёт сообщением Postgres, страница останется прежней.
- Запросы чтения выполняются в read-only транзакции, так что через `where` ничего не изменить.

Листать удобнее через `ctrl-.` → **zpg: Next page / Previous page**. *Next page* предлагается, только когда страница заполнена до `limit`. Если следующая страница оказалась пустой, придёт сообщение «no more rows», и останется текущая.

## Code actions

`ctrl-.` в файле таблицы:

| Действие | Когда доступно | Что делает |
|---|---|---|
| **zpg: Apply changes (…)** | есть незаписанные правки | записывает их в базу. Файл должен быть сохранён |
| **zpg: Preview SQL** | есть незаписанные правки | открывает SQL, который выполнится |
| **zpg: Open row** | курсор на строке данных | открывает строку вертикально |
| **zpg: Sort by … ↑ / ↓** | курсор на имени колонки, нет незаписанных правок | сортирует страницу по этой колонке |
| **zpg: Insert row** | таблица редактируема | вставляет заготовку новой строки под курсором |
| **zpg: Next page / Previous page** | нет незаписанных правок | соседняя страница |
| **zpg: Refresh** | всегда | перечитывает страницу и структуру таблицы из базы. С правками называется *Refresh (discard changes)* и отбрасывает их |
| **zpg: Apply changes manually / on save** | всегда | переключает `apply=` в шапке |

В просмотре строки: **zpg: Apply changes**, **zpg: Refresh row (discard changes)**.
В `.sql`: **zpg: Run statement on …**, **zpg: Run selection on …**.
В результате запроса: **zpg: Edit rows in table**, **zpg: Run again**.
В каталоге: **zpg: Open <таблица>**, **zpg: Drop <таблица>…**, **zpg: Refresh catalog** и **zpg: Open settings file**.

## Ошибки и что с ними делать

| Сообщение | Причина | Что делать |
|---|---|---|
| `duplicate key: this row appears twice` | одна и та же строка (по ключу) встречается дважды | удалите копию или поменяйте ключ / поставьте `+` |
| `value is cut to fit the line…` | правка обрезанного значения | откройте строку (F12 на ключе), увеличьте `width` или сократите `columns` |
| `row has N cells, the page shows M columns` | стёрт или добавлен лишний `\|` | восстановите разметку строки |
| `a new row needs …: add to columns=` | в новой строке не хватает обязательной скрытой колонки | добавьте её в `columns=` |
| `` `columns`: no such column … `` | опечатка в `columns=` | исправьте имя (подскажет автодополнение) |
| `rows are N characters and Zed wraps lines over 512…` | таблица не влезает даже после сужения колонок | оставьте нужные колонки через `columns=` |
| `column row must stay …` | изменена строка с именами колонок | верните её как была |
| `expected field …`, `missing field …` | в просмотре строки удалено или переставлено поле | верните поле на место |
| `key fields can't be changed here` | в просмотре строки изменён ключ | ключ меняется только в таблице |
| `read-only: …` | у таблицы нет PK, это view или подключение `read_only` | такую таблицу можно только смотреть |
| `row was changed or deleted since it was loaded` | строку изменили в базе после загрузки | **Refresh**, затем правьте заново |
| `not saved: <ошибка Postgres>` | база отклонила запрос (NOT NULL, FK, unique, тип) | исправьте значение в указанной строке |
| `no saved state for this file` | файл открыт не из каталога или удалён `.state` | **Refresh** (для таблицы) или откройте заново из каталога |
| `! …` в каталоге | не удалось подключиться | проверьте строку подключения и переменные окружения |
| `…/config.json: …` | ошибка в файле настроек (JSON) | исправьте место, указанное в сообщении; до исправления действуют прежние настройки |
| ``no connection `x` in …`` | в файле таблицы подключение, которого нет в настройках | добавьте его в `~/.config/zpg/config.json` |
| `environment variable X is not set` | в URL есть `${X}`, а переменной нет | задайте переменную и перезапустите Zed |
| `ssh to …: Host key verification failed` | сервера нет в `known_hosts` | один раз зайдите на сервер `ssh` из терминала |
| `ssh to …: Permission denied (publickey…)` | ключ не подошёл или не загружен в agent | `ssh-add`, проверьте `~/.ssh/config`; вход по паролю не поддерживается |
| `ssh to …: no tunnel after 20 s` | ssh завис на подключении | проверьте доступность сервера и `ProxyJump` |
| ошибка на запросе в `.sql` | Postgres отклонил запрос, всё откачено | исправьте подчёркнутое место и запустите снова |
| `read-only: query result…` в `.pgres` | результат запроса правится не здесь | **Edit rows in table** |
| `the query has a string spanning lines…` | для «Edit rows in table» запрос должен уместиться в одну строку шапки | уберите перевод строки из строкового литерала |
| нет кнопок ▶ над запросами | не установлено расширение SQL, выключены code lens или нет подключений | см. [Установка](#установка) и [Подключения](#подключения) |

Сообщения сервера (`zpg: saved…`, ошибки) всплывают в правом нижнем углу Zed. Подробный лог: `ctrl-shift-p` → **dev: open language server logs** → `zpg`.

## Файлы в .zpg

```
.zpg/
├── .gitignore                       # «*»: папка не попадает в git
├── catalog.pgdb                     # каталог
└── local/                           # по папке на подключение
    ├── public.orders.pgt            # страница таблицы
    ├── public.orders.preview.sql    # последний Preview SQL
    ├── results/
    │   └── report.pgres             # результат последнего запуска из report.sql
    ├── public.orders.rows/
    │   ├── 1.pgr                    # просмотр строки с ключом 1
    │   └── .state/
    └── .state/
        └── public.orders.pgt.json   # что было загружено из базы — с ним сравниваются правки
```

- `.state/*.json` нужен, чтобы понять, что именно вы изменили. Не удаляйте его, пока в файле есть незаписанные правки.
- Всю папку `.zpg` можно удалить в любой момент, когда нет незаписанных правок. Она пересоздастся при следующем открытии.
- Значения таблиц лежат на диске в открытом виде. Учитывайте это для чувствительных данных.

## Ограничения

- Это текст, а не грид. Таблицы прокручиваются по горизонтали, поэтому для `.pgt` удобно выключить перенос строк (`"soft_wrap": "none"`). Строки длиннее 512 символов Zed переносит в любом случае, см. [Широкие таблицы](#страница-таблицы).
- Пока идёт запрос, zpg не отвечает на другие действия (hover, автодополнение) — для долгих запросов есть `statement_timeout_ms`.
- Параметры `$1` в запросах и `psql`-команды (`\d`, `\copy`) не поддерживаются.
- Страница загружается целиком в буфер. Для больших таблиц используйте `where` и `limit`, а не листайте тысячи страниц.
- В режиме `apply=save` каждое сохранение сразу пишется в базу. С включённым автосохранением Zed (`"autosave"`) используйте только `manual`.
