# Catalog

The catalog, `.zpg/catalog.pgdb` at the project root, is the entry point: every connection from the settings and its tables. It opens with the **zpg: open catalog** task or `zpg open` from a terminal, see [Installation](01-install.md#5-a-task-to-open-the-catalog).

```
# zpg v1 catalog
# Go to definition (F12) on a table opens it; code actions refresh.

[local]
zpg_demo.customers    table       ~8 rows
zpg_demo.events       table       ~40 rows
zpg_demo.order_items  table       ~14 rows
zpg_demo.orders       table       ~9 rows
zpg_demo.paid_orders  view
zpg_demo.products     table       ~6 rows

[prod]
! password authentication failed for user "app"
```

- **`[name]`** is a connection from the settings. Under it are the tables (`table`, `partitioned`), views, materialized views (`matview`) and foreign tables (`foreign`) the user has `SELECT` on. Partitions aren't listed separately, only the parent table. System schemas are hidden.
- **`~N rows`** is an approximate row count. It is the server statistics' count of live rows (`n_live_tup`): it updates after every commit without waiting for `ANALYZE`. But it gets its starting point only from `VACUUM`/`ANALYZE`; if neither has run since the statistics were reset (`pg_stat_reset()`, a crash or an immediate shutdown of the server), the planner's estimate (`reltuples`) plus the rows inserted and deleted since the reset is shown. The number is approximate; the exact one is [`total`](05-table.md#how-many-rows-in-total) on the table page.
- **`! …`** is a connection error: a wrong password, an unreachable host, an ssh error. Fix the [settings](02-connections.md) and the catalog refreshes by itself.
- With no connections, the catalog shows how to add them.

## Opening a table

Cursor on a table line → **F12** (or `ctrl`+click, or `ctrl-.` → **zpg: Open zpg_demo.orders**). The first page of the table opens as `.zpg/local/zpg_demo.orders.pgt`, see [Table page](05-table.md).

If the table was opened before, the existing file opens as it is, with all unwritten edits. **Refresh** on the table page loads fresh data.

## Finding a table

- **The Outline panel** or `ctrl-shift-o` in the catalog show the connections and tables and can be searched. The list is flat: `[local]`, then its tables.
- **`ctrl-t`** (project symbols) finds a table from any file. The letters of the query must appear in the name in order: `zdord` finds `zpg_demo.orders`. If the table already has a page, that opens; otherwise its catalog line does, and **F12** from there.

`ctrl-t` reads the file `.zpg/catalog.pgdb` and doesn't query the database, so it sees the tables as of the catalog's last refresh. The catalog must have been opened at least once, and the zpg server must be running, that is, one of its files must be open (`.pgdb`, `.pgt`, `.pgr`, `.pgres`, `.sql`).

## Hover: columns, size, indexes

Hover a table line:

```
zpg_demo.orders · table · ~9 rows · 64 kB

- `id` bigint · not null · has default
- `customer_id` bigint · not null
- `status` zpg_demo.order_status · not null · has default
- `created_at` timestamp with time zone · not null · has default
- `total` numeric(12,2) · not null · has default — Computed by the order_items_total trigger
- `comment` text

Indexes
- orders_pkey — primary key, btree (id)
- orders_customer_idx — btree (customer_id)
- orders_open_idx — btree (created_at) WHERE (status = ANY (…))
```

The size is `pg_total_relation_size`, so it includes indexes and TOAST. After `— …` comes the column's comment (`COMMENT ON COLUMN`). The table's comment is shown under the title.

## Table structure (DDL)

`ctrl-.` on a table line → **zpg: Show DDL of zpg_demo.orders**. `.zpg/local/zpg_demo.orders.ddl.sql` opens:

```sql
-- @conn local
-- zpg_demo.orders, rebuilt by zpg from the system catalogs (owners, grants and storage options are left out).

CREATE TABLE zpg_demo.orders (
    id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    customer_id bigint NOT NULL,
    status zpg_demo.order_status DEFAULT 'new'::zpg_demo.order_status NOT NULL,
    created_at timestamp with time zone DEFAULT now() NOT NULL,
    total numeric(12,2) DEFAULT 0 NOT NULL,
    comment text,
    CONSTRAINT orders_pkey PRIMARY KEY (id),
    CONSTRAINT orders_customer_id_fkey FOREIGN KEY (customer_id) REFERENCES zpg_demo.customers(id) ON DELETE CASCADE
);

CREATE INDEX orders_customer_idx ON zpg_demo.orders USING btree (customer_id);
CREATE INDEX orders_open_idx ON zpg_demo.orders USING btree (created_at) WHERE (status = ANY (ARRAY['new'::zpg_demo.order_status, 'paid'::zpg_demo.order_status]));
COMMENT ON COLUMN zpg_demo.orders.total IS 'Computed by the order_items_total trigger';
```

What's included:

- columns with types, `DEFAULT`, `GENERATED … AS IDENTITY`, `GENERATED ALWAYS AS (…) STORED`, `COLLATE`, `NOT NULL`;
- constraints: `PRIMARY KEY`, `UNIQUE`, `EXCLUDE`, `CHECK`, `FOREIGN KEY`;
- `UNLOGGED`, `PARTITION BY`, and `SERVER … OPTIONS (…)` for a foreign table;
- standalone indexes (not created by constraints), triggers, `COMMENT ON TABLE` and `COMMENT ON COLUMN`;
- for views and materialized views, `CREATE [MATERIALIZED] VIEW … AS` with the query text.

The DDL is assembled from the system catalog, not with `pg_dump`: owners, grants (`GRANT`) and storage options are left out. It is an ordinary `.sql` file with `-- @conn`, so you can run statements from it right away, for example add an `ALTER TABLE` and press ▶.

The same from a table page: `ctrl-.` → **zpg: Show DDL**.

## Table backup (pg_dump)

`ctrl-.` on a table line → **zpg: Back up zpg_demo.orders (pg_dump)**. zpg runs `pg_dump --table zpg_demo.orders` and saves the output to `.zpg/local/backups/zpg_demo.orders-20261018-021333.sql`: the table's structure, its indexes, constraints, triggers and all its data. At the bottom: `zpg: backed up zpg_demo.orders to .zpg/local/backups/… (7 kB)`, and the file opens.

```sql
-- zpg: pg_dump of zpg_demo.orders on local, 2026-10-18 02:13:33.
-- Restore with psql (it has COPY data that ▶ can't run): psql -d <database> -f <this file>

--
-- PostgreSQL database dump
--
…
CREATE TABLE zpg_demo.orders ( … );
…
COPY zpg_demo.orders (id, customer_id, status, created_at, total, comment) FROM stdin;
1	1	paid	2026-09-28 01:40:44.321115+05	64.90	\N
…
\.
```

- It needs `pg_dump` from the PostgreSQL client tools (`postgresql-client`), not older than the server. If it isn't in `PATH` or you need another version, set its path in the `"pg_dump"` setting, see [Connections](02-connections.md#all-settings).
- The connection is the same as zpg's, including the SSH tunnel; the password is passed in the `PGPASSWORD` environment variable, not on the command line.
- While `pg_dump` runs, the status bar shows **zpg: pg_dump of …**; to cancel: `ctrl-.` → **zpg: Cancel pg_dump of …**. The unfinished file is deleted.
- Extra arguments go in the `"pg_dump_args"` setting and are added to every run:

  | `pg_dump_args` | What you get |
  |---|---|
  | `[]` (default) | an SQL file: `CREATE TABLE` + data via `COPY` |
  | `["--data-only"]` | data only |
  | `["--schema-only"]` | structure only |
  | `["--clean", "--if-exists"]` | `DROP TABLE IF EXISTS` at the start, to restore over an existing table |
  | `["--column-inserts"]` | data as `INSERT`; such a file can be run from zpg too (select all → **Run selection**) |
  | `["-Fc"]` | `pg_dump`'s compressed format → a `.dump` file for `pg_restore`, not opened in the editor |

- **To restore**: `psql -d database -f file.sql` (or `pg_restore -d database file.dump`). A plain SQL backup can't be run from zpg: its data comes in a `COPY … FROM stdin` block that only `psql` understands.
- The backup is of what's in the database: unwritten edits on the page aren't in it.

From the table's own page: `ctrl-.` → **zpg: Back up … (pg_dump)**.

## Dropping a table

`ctrl-.` on a table line → **zpg: Drop zpg_demo.events…**. zpg doesn't drop anything itself; it opens `.zpg/local/drop-zpg_demo.events.sql` with the statement ready:

```sql
-- @conn local
-- Review, then run with ▶ (or ctrl-. → Run statement). This can't be undone.
-- Add CASCADE to also drop views and foreign keys that depend on it.
DROP TABLE zpg_demo.events;
```

The object type is filled in: `DROP TABLE`, `DROP VIEW`, `DROP MATERIALIZED VIEW` or `DROP FOREIGN TABLE`. Press ▶ and zpg asks for confirmation once more ([dangerous statements](08-sql.md#dangerous-statements)). To drop dependent objects too, add `CASCADE`.

## Refreshing the catalog

`ctrl-.` → **zpg: Refresh catalog**. After `CREATE`, `DROP` and `ALTER` run from `.sql`, the catalog refreshes by itself, and also when the settings file changes.

## Other actions

On any line of a connection's section: **zpg: Server activity of local** shows who is connected to the server and what they run, see [Administration](09-admin.md). **zpg: Databases of local** lists the server's databases, see [there](09-admin.md#databases); **zpg: Schemas of local** lists the schemas, empty ones included, see [there](09-admin.md#schemas).

Anywhere in the catalog: **zpg: Open settings file**.
