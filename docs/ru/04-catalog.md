# Каталог

Каталог — `.zpg/catalog.pgdb` в корне проекта — точка входа: все подключения из настроек и их таблицы. Открывается задачей **zpg: open catalog** или `zpg open` из терминала, см. [Установка](01-install.md#5-задача-открыть-каталог).

```
# zpg v1 catalog
# Go to definition (F12) on a table opens it; code actions refresh.

[local]
zpg_demo.customers    table       ~8 rows
zpg_demo.events       table       ~40 rows
zpg_demo.order_items  table       ~14 rows
zpg_demo.orders       table       ~9 rows
zpg_demo.paid_orders  view
zpg_demo.products     table       ~6 rows

[prod]
! password authentication failed for user "app"
```

- **`[имя]`** — подключение из настроек. Под ним таблицы (`table`, `partitioned`), view, materialized view (`matview`) и foreign tables (`foreign`), на которые у пользователя есть право `SELECT`. Партиции отдельно не показываются, только родительская таблица. Системные схемы скрыты.
- **`~N rows`** — примерное число строк. Это счётчик живых строк из статистики сервера (`n_live_tup`): он обновляется после каждого коммита, не дожидаясь `ANALYZE`. Но точку отсчёта он получает только от `VACUUM`/`ANALYZE`; если их не было с момента сброса статистики (`pg_stat_reset()`, падение или жёсткий перезапуск сервера), показывается оценка планировщика (`reltuples`) плюс строки, вставленные и удалённые после сброса. Цифра приблизительная; точное число показывает [`total`](05-table.md#сколько-всего-строк) на странице таблицы.
- **`! …`** — ошибка подключения: неверный пароль, недоступный хост, ошибка ssh. Исправьте [настройки](02-connections.md), каталог обновится сам.
- Если подключений нет, в каталоге будет подсказка, как их добавить.

## Открыть таблицу

Курсор на строке таблицы → **F12** (или `ctrl`+клик, или `ctrl-.` → **zpg: Open zpg_demo.orders**). Откроется первая страница таблицы как `.zpg/local/zpg_demo.orders.pgt`, см. [Страница таблицы](05-table.md).

Если таблица уже открывалась, откроется существующий файл как есть, со всеми незаписанными правками. Свежие данные загружает **Refresh** на странице таблицы.

## Hover: колонки, размер, индексы

Наведите курсор на строку таблицы:

```
zpg_demo.orders · table · ~9 rows · 64 kB

- `id` bigint · not null · has default
- `customer_id` bigint · not null
- `status` zpg_demo.order_status · not null · has default
- `created_at` timestamp with time zone · not null · has default
- `total` numeric(12,2) · not null · has default — Считается триггером order_items_total
- `comment` text

Indexes
- orders_pkey — primary key, btree (id)
- orders_customer_idx — btree (customer_id)
- orders_open_idx — btree (created_at) WHERE (status = ANY (…))
```

Размер — `pg_total_relation_size`, то есть вместе с индексами и TOAST. После `— …` — комментарий колонки (`COMMENT ON COLUMN`). Комментарий таблицы показывается под заголовком.

## Структура таблицы (DDL)

`ctrl-.` на строке таблицы → **zpg: Show DDL of zpg_demo.orders**. Откроется `.zpg/local/zpg_demo.orders.ddl.sql`:

```sql
-- @conn local
-- zpg_demo.orders, rebuilt by zpg from the system catalogs (owners, grants and storage options are left out).

CREATE TABLE zpg_demo.orders (
    id bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    customer_id bigint NOT NULL,
    status zpg_demo.order_status DEFAULT 'new'::zpg_demo.order_status NOT NULL,
    created_at timestamp with time zone DEFAULT now() NOT NULL,
    total numeric(12,2) DEFAULT 0 NOT NULL,
    comment text,
    CONSTRAINT orders_pkey PRIMARY KEY (id),
    CONSTRAINT orders_customer_id_fkey FOREIGN KEY (customer_id) REFERENCES zpg_demo.customers(id) ON DELETE CASCADE
);

CREATE INDEX orders_customer_idx ON zpg_demo.orders USING btree (customer_id);
CREATE INDEX orders_open_idx ON zpg_demo.orders USING btree (created_at) WHERE (status = ANY (ARRAY['new'::zpg_demo.order_status, 'paid'::zpg_demo.order_status]));
COMMENT ON COLUMN zpg_demo.orders.total IS 'Считается триггером order_items_total';
```

Что входит:

- колонки с типами, `DEFAULT`, `GENERATED … AS IDENTITY`, `GENERATED ALWAYS AS (…) STORED`, `COLLATE`, `NOT NULL`;
- ограничения: `PRIMARY KEY`, `UNIQUE`, `EXCLUDE`, `CHECK`, `FOREIGN KEY`;
- `UNLOGGED`, `PARTITION BY`, для foreign table — `SERVER … OPTIONS (…)`;
- отдельные индексы (не созданные ограничениями), триггеры, `COMMENT ON TABLE` и `COMMENT ON COLUMN`;
- для view и materialized view — `CREATE [MATERIALIZED] VIEW … AS` с текстом запроса.

DDL собирается из системного каталога, а не через `pg_dump`: владельцы, права (`GRANT`) и параметры хранения не выводятся. Это обычный `.sql`-файл с `-- @conn`, поэтому из него можно сразу запускать запросы, например дописать `ALTER TABLE` и нажать ▶.

То же со страницы таблицы: `ctrl-.` → **zpg: Show DDL**.

## Бэкап таблицы (pg_dump)

`ctrl-.` на строке таблицы → **zpg: Back up zpg_demo.orders (pg_dump)**. zpg запускает `pg_dump --table zpg_demo.orders` и сохраняет результат в `.zpg/local/backups/zpg_demo.orders-20261018-021333.sql` — структуру таблицы, её индексы, ограничения, триггеры и все данные. Внизу: `zpg: backed up zpg_demo.orders to .zpg/local/backups/… (7 kB)`, файл откроется.

```sql
-- zpg: pg_dump of zpg_demo.orders on local, 2026-10-18 02:13:33.
-- Restore with psql (it has COPY data that ▶ can't run): psql -d <database> -f <this file>

--
-- PostgreSQL database dump
--
…
CREATE TABLE zpg_demo.orders ( … );
…
COPY zpg_demo.orders (id, customer_id, status, created_at, total, comment) FROM stdin;
1	1	paid	2026-09-28 01:40:44.321115+05	64.90	\N
…
\.
```

- Нужен `pg_dump` из клиентских утилит PostgreSQL (`postgresql-client`), не старше сервера. Если он не в `PATH` или нужна другая версия, укажите путь в настройке `"pg_dump"`, см. [Подключения](02-connections.md#все-параметры).
- Подключение то же, что у zpg, включая SSH-туннель; пароль передаётся через переменную окружения `PGPASSWORD`, а не в командной строке.
- Пока `pg_dump` работает, в строке состояния **zpg: pg_dump of …**; отменить — `ctrl-.` → **zpg: Cancel pg_dump of …**. Недописанный файл удаляется.
- Дополнительные аргументы — настройка `"pg_dump_args"`, добавляется к каждому запуску:

  | `pg_dump_args` | Что получится |
  |---|---|
  | `[]` (по умолчанию) | SQL-файл: `CREATE TABLE` + данные через `COPY` |
  | `["--data-only"]` | только данные |
  | `["--schema-only"]` | только структура |
  | `["--clean", "--if-exists"]` | в начале `DROP TABLE IF EXISTS`, чтобы восстановить поверх существующей таблицы |
  | `["--column-inserts"]` | данные как `INSERT` — такой файл можно выполнить и из zpg (выделить всё → **Run selection**) |
  | `["-Fc"]` | сжатый формат `pg_dump` → файл `.dump` для `pg_restore`, в редакторе не открывается |

- **Восстановить**: `psql -d база -f файл.sql` (или `pg_restore -d база файл.dump`). Из zpg обычный SQL-бэкап выполнить нельзя: данные в нём идут блоком `COPY … FROM stdin`, который понимает только `psql`.
- Бэкап — того, что в базе: незаписанные правки страницы в него не попадают.

С той же таблицы на её странице: `ctrl-.` → **zpg: Back up … (pg_dump)**.

## Удалить таблицу

`ctrl-.` на строке таблицы → **zpg: Drop zpg_demo.events…**. zpg ничего не удаляет сам, а открывает `.zpg/local/drop-zpg_demo.events.sql` с готовым запросом:

```sql
-- @conn local
-- Review, then run with ▶ (or ctrl-. → Run statement). This can't be undone.
-- Add CASCADE to also drop views and foreign keys that depend on it.
DROP TABLE zpg_demo.events;
```

Тип объекта подставляется сам: `DROP TABLE`, `DROP VIEW`, `DROP MATERIALIZED VIEW` или `DROP FOREIGN TABLE`. Нажмите ▶ — zpg ещё раз спросит подтверждение ([опасные запросы](08-sql.md#опасные-запросы)). Чтобы удалить и зависимые объекты, допишите `CASCADE`.

## Обновить каталог

`ctrl-.` → **zpg: Refresh catalog**. После `CREATE`, `DROP` и `ALTER`, запущенных из `.sql`, каталог обновляется сам, а при изменении файла настроек — тоже.

## Другие действия

На любой строке секции подключения: **zpg: Server activity of local** — кто подключён к серверу и что выполняет, см. [Администрирование](09-admin.md).

В любом месте каталога: **zpg: Open settings file**.
