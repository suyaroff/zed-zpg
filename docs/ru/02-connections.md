# Подключения и настройки

Все настройки zpg лежат в одном файле пользователя — `~/.config/zpg/config.json`. Он общий для всех проектов и лежит вне их, поэтому пароли не попадут в git. Настройки Zed (`lsp.zpg.settings`, `.zed/settings.json`) zpg не читает.

## Файл настроек

Файл создаётся сам при первом запуске zpg, с примерами в комментариях. Открыть его:

- в каталоге: `ctrl-.` → **zpg: Open settings file**;
- из терминала: `zpg config`.

Пример:

```jsonc
{
  "connections": {
    // локальная база через unix-сокет
    "local": "postgresql:///shop?host=/var/run/postgresql",
    // тестовый сервер по сети
    "stage": "postgresql://app:secret@stage-db:5432/shop",
    // боевая база: только чтение, через SSH
    "prod": {
      "url": "postgresql:///shop?host=/var/run/postgresql",
      "ssh": "deploy@prod.example.com",
      "read_only": true
    },
  },
  "page_size": 100,
  "apply": "manual",
}
```

- Можно писать комментарии `//` и `/* */` и оставлять запятую после последнего элемента, как в настройках Zed.
- Изменения применяются при следующем действии zpg, перезапускать ничего не нужно. Открытый каталог обновится сам.
- Если в файле ошибка, zpg покажет её сообщением и продолжит работать с прежними настройками.
- Права на файл — `600` (читает только владелец).
- Другой путь задаётся переменной `ZPG_CONFIG`. По умолчанию учитывается `XDG_CONFIG_HOME`; на Windows файл лежит в `%APPDATA%\zpg\config.json`.

## Все параметры

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `connections` | — | имя подключения → строка подключения или объект (см. ниже) |
| `page_size` | `100` | сколько строк загружать на страницу таблицы (1–10 000) |
| `max_cell_width` | `40` | ширина, после которой значение в ячейке обрезается до `…` |
| `apply` | `"manual"` | режим записи для вновь открываемых таблиц: `manual` или `save`, см. [Редактирование](06-editing.md#когда-изменения-уходят-в-базу) |
| `max_result_rows` | `1000` | сколько строк результата показывать при запуске SQL (1–100 000) |
| `statement_timeout_ms` | `60000` | таймаут одного запуска SQL в миллисекундах, `0` — без таймаута |
| `check_sql` | `true` | проверять запросы в `.sql` при открытии и сохранении, см. [Проверка запросов](08-sql.md#проверка-запросов) |
| `pg_dump` | `"pg_dump"` | программа для [бэкапа таблицы](04-catalog.md#бэкап-таблицы-pg_dump), например `"/usr/lib/postgresql/16/bin/pg_dump"` |
| `pg_dump_args` | `[]` | дополнительные аргументы `pg_dump`, например `["--column-inserts"]` |

Подключение — строка или объект:

| Поле объекта | Что делает |
|---|---|
| `url` | строка подключения |
| `read_only` | `true` — только чтение, см. [ниже](#только-чтение) |
| `ssh` | `user@host` или имя из `~/.ssh/config` — подключаться через SSH-туннель |
| `ssh_options` | дополнительные аргументы `ssh`, например `["-p", "2222"]` |

## Строка подключения

Подходят оба формата libpq:

| Случай | Пример |
|---|---|
| локально через unix-сокет | `postgresql:///shop?host=/var/run/postgresql` |
| то же, формат key=value | `host=/var/run/postgresql dbname=shop` |
| по сети с паролем | `postgresql://app:secret@db.example.com:5432/shop` |
| без TLS | `postgresql://app@db.example.com/shop?sslmode=disable` |

- **Пользователь** по умолчанию — `$USER`.
- **Пароль** можно писать прямо в URL: файл настроек лежит вне проектов. Если хочется держать его в переменной окружения, используйте `${VAR}`: значение берётся из окружения проекта (direnv или окружение, из которого запущен Zed). Если переменной нет, будет ошибка `environment variable X is not set`.

  ```json
  "stage": "postgresql://app:${STAGE_PG_PASSWORD}@stage-db/shop"
  ```

- **TLS.** `sslmode=prefer` (по умолчанию) и `require` шифруют соединение без проверки сертификата, как libpq. `verify-ca` и `verify-full` не поддерживаются. Unix-сокеты и `sslmode=disable` работают без TLS.
- zpg представляется серверу как `application_name=zpg` — его сессии видно в [активности сервера](09-admin.md).

## Только чтение

```json
"prod": { "url": "postgresql://app@prod-db/shop", "read_only": true }
```

С `read_only: true`:

- все таблицы подключения открываются только для чтения — правки подсвечиваются ошибкой и не записываются;
- каждая транзакция открывается read-only (`default_transaction_read_only=on`), так что и запросы из `.sql` ничего не изменят: Postgres отклонит `UPDATE`, `DELETE`, DDL;
- zpg не задаёт вопрос перед [опасными запросами](08-sql.md#опасные-запросы) — они всё равно не пройдут.

Включайте это для боевых баз.

## Через SSH

Если база доступна только с сервера, добавьте `ssh`. zpg сам поднимет туннель через системный `ssh` и закроет его при выходе:

```json
"prod": {
  "url": "postgresql:///shop?host=/var/run/postgresql",
  "ssh": "deploy@prod.example.com",
  "read_only": true
},
"stage": {
  "url": "postgresql://app:${STAGE_PG_PASSWORD}@10.0.0.5:5432/shop",
  "ssh": "stage-bastion",
  "ssh_options": ["-p", "2222"]
}
```

- **`url`** описывает базу так, как её видит сервер. `host=/var/run/postgresql` — unix-сокет Postgres на сервере: тогда работает peer-аутентификация от имени SSH-пользователя, пароль БД не нужен. `10.0.0.5:5432` — база во внутренней сети сервера.
- **`ssh`** — `user@host` или имя хоста из `~/.ssh/config`. Ключи, ssh-agent, `ProxyJump` через бастион и порт берутся оттуда же.
- **Только ключ или agent.** Пароль SSH zpg спросить не сможет. Сервер должен быть в `known_hosts`: один раз зайдите на него `ssh deploy@prod.example.com` из терминала.
- **Упал туннель** (сеть, сон ноутбука) — следующий запрос поднимет его заново.
- **Ошибки ssh** (`Permission denied`, `Host key verification failed`) видны в каталоге под именем подключения.

## Несколько подключений

- Каталог показывает все подключения, каждое своей секцией `[имя]`.
- В `.sql`-файлах подключение выбирается строкой `-- @conn имя`; без неё при нескольких подключениях над запросом будет по кнопке на каждое, см. [SQL-файлы](08-sql.md#подключение).
