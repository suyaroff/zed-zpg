# Страница таблицы

Страница — файл `.zpg/<подключение>/<схема>.<таблица>.pgt`: одна страница строк таблицы в виде текстовой таблицы. Открывается **F12** в [каталоге](04-catalog.md#открыть-таблицу), по [внешнему ключу](07-relations.md) или из `.sql` (**F12** на имени таблицы).

```
# zpg v1 conn=local table=zpg_demo.customers pk=id page=1 limit=100 total=8 width=40 apply=manual
| id | email               | name             | city      | vip   | created_at                    | note                                     |
|----|---------------------|------------------|-----------|-------|-------------------------------|------------------------------------------|
| 1  | anna@example.com    | Анна Петрова     | Ташкент   | true  | 2026-10-18 01:40:44.321115+05 | NULL                                     |
| 4  | dilnoza@example.com | Дилноза Каримова | Самарканд | true  | 2026-10-18 01:40:44.321115+05 | Две строки:\nвторая строка               |
| 8  | hiro@example.com    | Hiro Tanaka      | Osaka     | false | 2026-10-18 01:40:44.321115+05 | Очень длинная заметка о клиенте, котора… |
```

- **Строка 1 — шапка**: какие строки показаны и как записывать, см. [ниже](#шапка).
- **Строка 2 — имена колонок.** Менять нельзя.
- **Строка 3 — разделитель.** Выравнивается сам.
- **Дальше — строки данных.** Значения в текстовом виде Postgres: `true`/`false`, даты `2026-10-18 01:40:44+05`, JSON как есть, массивы `{periphery,usb}`. `NULL` — это SQL NULL; перевод строки внутри значения показан как `\n`, см. [Специальные значения](06-editing.md#специальные-значения).
- **`…` в конце** — значение длиннее `width` и обрезано. Полное значение покажет hover или [просмотр строки](07-relations.md#просмотр-строки).

## Шапка

Первая строка управляет страницей. Поменяйте её и сохраните (`ctrl-s`) — страница загрузится заново.

```
# zpg v1 conn=local table=zpg_demo.events pk="" page=1 limit=20 total=10 width=60 apply=manual where="level = 'error'" order="at desc" columns="at, message"
```

| Поле | Что делает | Пример |
|---|---|---|
| `page` | номер страницы, с 1 | `page=3` |
| `limit` | строк на странице, до 10 000 | `limit=500` |
| `where` | SQL-условие фильтра | `where="created_at > now() - interval '1 day'"` |
| `order` | SQL-сортировка; без поля — по ключу | `order="created_at desc, id"` |
| `columns` | какие колонки показывать; без поля — все | `columns="name, email"` |
| `width` | ширина обрезки значений, `0` — не обрезать | `width=0` |
| `apply` | когда записывать в базу: `manual` или `save` | `apply=save` |
| `conn`, `table`, `pk`, `total` | только для информации, менять нельзя | |

- `where`, `order` и `columns` можно писать без кавычек: значение тянется до следующего поля шапки. `order=id desc` и `where=vip and city = 'Ташкент'` работают как есть, при сохранении zpg сам возьмёт их в кавычки.
- Остальные значения с пробелами пишутся в двойных кавычках, кавычка внутри — `\"`. Одинарные кавычки SQL пишутся как есть.
- Чтобы убрать фильтр или сортировку, удалите поле целиком.
- Ошибка в `where`/`order` придёт сообщением Postgres, страница останется прежней.
- Страницы читаются в read-only транзакции, так что через `where` ничего не изменить.
- Если на странице есть незаписанные правки: в режиме `manual` новая шапка не применится, пока вы не запишете или не отмените правки; в режиме `save` правки сначала запишутся, потом загрузится новая страница.
- Автодополнение в шапке: внутри `where="…"` — колонки и `and`, `or`, `is null`, `like`…; внутри `order="…"` — колонки и `asc`, `desc`, `nulls last`; вне значений — имена полей.

### Примеры шапки

```
# заказы последней недели, новые сверху
… where="created_at > now() - interval '7 days'" order="created_at desc"

# только VIP из Ташкента, три колонки
… where="vip and city = 'Ташкент'" columns="name, email, city"

# товары, у которых в attrs есть "wireless": true
… where="attrs @> '{\"wireless\": true}'"

# заказы покупателей, у которых больше одного заказа
… where="customer_id in (select customer_id from zpg_demo.orders group by 1 having count(*) > 1)"

# показать длинные значения целиком
… width=0
```

## Сколько всего строк

`total` в шапке — сколько строк подходит под `where`:

- при загрузке zpg считает их `count(*)`; если подсчёт не уложился в секунду, показывает оценку планировщика с `~`, например `total=~1200000`;
- при листании и сортировке число не пересчитывается, при **Refresh** и смене `where` — пересчитывается;
- после записи zpg прибавляет вставленные строки и вычитает удалённые; если задан `where`, число становится оценкой (`~`) — новые строки могут под него не подходить.

## Листать страницы

`ctrl-.` → **zpg: Next page (2/37)**, **Previous page**, **First page**, **Last page (37/37)**. В названии — номер страницы из общего числа (по `total`). *Next* и *Last* предлагаются, только когда текущая страница заполнена до `limit`. Если следующая страница оказалась пустой, придёт «no more rows», и останется текущая.

Можно и руками: `page=5` в шапке и `ctrl-s`.

## Сортировка

Курсор на имени колонки в строке заголовков → `ctrl-.` → **zpg: Sort by created_at ↑** (по возрастанию) или **↓** (по убыванию). Страница перезагрузится с первой страницы, в шапке появится `order=created_at desc`.

## Фильтр по значению ячейки

Курсор на ячейке → `ctrl-.`:

| Ячейка | Действия |
|---|---|
| `Ташкент` в колонке `city` | **zpg: Filter: city = 'Ташкент'**, **zpg: Filter: city <> 'Ташкент'** |
| `NULL` в колонке `city` | **zpg: Filter: city IS NULL**, **zpg: Filter: city IS NOT NULL** |

- Если `where` уже задан, условие добавляется через `AND` — действие называется **Also filter: …**. Так можно сужать выборку по шагам: сначала `city = 'Ташкент'`, потом `vip = 'true'`.
- Берётся полное значение из базы, даже если в ячейке оно обрезано.
- Значения длиннее 200 символов и многострочные не предлагаются.
- Для `json`, `xml` и геометрических типов, у которых нет `=`, сравнивается текст: `attrs::text = '…'`.
- **zpg: Clear filter (where=)** убирает фильтр целиком.

## Выбор колонок

`columns="name, email"` показывает только эти колонки (плюс ключевые — они видны всегда):

- колонки идут в порядке таблицы, а не списка;
- скрытые колонки при записи не трогаются, в новых строках получают значение по умолчанию;
- если скрыта обязательная колонка (NOT NULL без значения по умолчанию), новая строка подсветится ошибкой «a new row needs …: add to columns=»;
- `columns` и `width` только перерисовывают уже загруженные строки, база не читается.

## Широкие таблицы

Zed всегда переносит строки длиннее 512 символов, что бы ни стояло в `soft_wrap`. Поэтому zpg держит строку таблицы короче 500 символов: если колонки не помещаются, самые широкие обрезаются до общей ширины (ключевые — никогда). Если и так не помещается, на строке заголовков появится подсказка — выберите колонки через `columns=`.

Для `.pgt` удобно выключить перенос: `"Pg Table": { "soft_wrap": "none" }` в настройках Zed.

## Подсветка и hover

Числа, `true`/`false`, `NULL`/`DEFAULT` и обрезанные значения выделяются цветом. С включёнными semantic tokens ([Установка](01-install.md#4-настройки-zed)) изменённые ячейки и новые строки подчёркнуты ещё до записи в базу.

**Hover** на ячейке показывает колонку и значение:

```
vip boolean · not null · has default

Скидка 10% на все заказы
```

— имя, тип, признаки (`primary key`, `not null`, `has default`, `generated`), внешний ключ (`→ zpg_demo.customers(id)`), комментарий колонки и, для ключа, кто на строку ссылается (`← referenced by zpg_demo.orders(customer_id)`). Для обрезанного значения — полное значение, а для некоторых типов — больше, чем помещается в ячейку:

| Тип | Что показывает hover |
|---|---|
| `json`, `jsonb` | отформатированный JSON с подсветкой (если значение обрезано) |
| `timestamptz` | день недели, «3 hours ago» / «in 2 days», время в UTC и в вашем часовом поясе |
| `timestamp` | день недели и «сколько прошло» в двух вариантах: если время записано в вашем поясе и если в UTC |
| `date` | день недели, «today», «tomorrow», «5 days ago» |
| `integer`, `bigint` из 10 или 13 цифр | дату, если это Unix-время в секундах или миллисекундах (2001–2100) |
| массивы | элементы по одному в строке: `[1] a`, `[2] b`, для многомерных `[1][2]` |
| `xml` | с отступами и подсветкой |
| `bytea` | размер; текст, если это UTF-8, иначе hex-дамп первых 256 байт |

Значения длиннее 20 000 символов в hover обрезаются, целиком их показывает [просмотр строки](07-relations.md#просмотр-строки). Hover на ячейке внешнего ключа показывает строку, на которую он ссылается.

## Структура и бэкап

`ctrl-.` → **zpg: Show DDL** — `CREATE TABLE` этой таблицы, **zpg: Back up … (pg_dump)** — бэкап структуры и данных. Подробно — в [каталоге](04-catalog.md#структура-таблицы-ddl).

## Обновить

`ctrl-.` → **zpg: Refresh** перечитывает страницу и структуру таблицы из базы. Если есть незаписанные правки, действие называется **Refresh (discard changes)** и отбрасывает их.

## Только чтение

Таблица открывается только для чтения, если у неё нет первичного ключа (как `zpg_demo.events`), если это view или materialized view (`zpg_demo.paid_orders`) или если у подключения стоит [`read_only`](02-connections.md#только-чтение). Шапка `pk=""` — признак таблицы без ключа. Смотреть, фильтровать, сортировать и экспортировать такие таблицы можно, править — нет.
