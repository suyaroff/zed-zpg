# Редактирование

Страница таблицы — обычный текст: меняйте ячейки, добавляйте и удаляйте строки как в любом файле. zpg сравнивает буфер с тем, что загрузил из базы, и превращает разницу в запросы.

## Изменить значение

Перепечатайте текст ячейки. Ширину колонок выравнивать не нужно: при сохранении таблица выровняется сама.

```
| 7  | gina@example.com    | Gina Rossi       | NULL      | false | …
                                                ↓
| 7  | gina@example.com    | Gina Rossi       | Milano | false | …
```

→ `UPDATE zpg_demo.customers SET city = 'Milano' WHERE id = 7` (меняются только изменённые колонки).

## Добавить строку

- **`ctrl-.` → zpg: Insert row** — под курсором появится заготовка: `+` в ключе, `DEFAULT` в колонках со значением по умолчанию, `NULL` в необязательных, пустые ячейки в обязательных:

  ```
  | + |  |  | NULL | DEFAULT | DEFAULT | NULL |
  ```

- **Вручную**: допишите строку, а в ключевой колонке поставьте `+` — ключ возьмётся из sequence или identity.
- **Копией**: строка с ключом, которого нет на странице, тоже новая. Удобно скопировать строку (`ctrl-alt-shift-down`) и поменять ключ.

Составной ключ (`zpg_demo.order_items`, ключ `order_id, product_id`) пишется полностью:

```
| order_id | product_id | qty | price  | amount  |
| 3        | 4          | 1   | 79.00  | DEFAULT |
```

`amount` — generated-колонка, в ней допустим только `DEFAULT`. После записи сработает триггер, и `total` заказа 3 пересчитается.

## Удалить строку

Удалите строку из файла целиком (`ctrl-shift-k`) → `DELETE … WHERE id = …`.

## Специальные значения

| Пишете | В базу уйдёт |
|---|---|
| `NULL` | SQL NULL |
| `DEFAULT` | значение по умолчанию колонки |
| `+` (только в ключевой колонке) | новая строка, ключ по умолчанию |
| пустая ячейка | пустая строка `''` |
| `\NULL`, `\DEFAULT`, `\+` | текст `NULL`, `DEFAULT`, `+` |

## Экранирование внутри значения

| Пишете | Означает |
|---|---|
| `\|` | символ `\|` (иначе это граница ячейки) |
| `\\` | обратный слэш |
| `\n`, `\t`, `\r` | перевод строки, табуляция, возврат каретки |
| `\s` | пробел в начале или конце значения (пробелы по краям ячейки обрезаются) |

Пример: `Две строки:\nвторая строка` в ячейке — это значение из двух строк. Длинный текст и JSON удобнее править в [просмотре строки](07-relations.md#просмотр-строки): там переводы строк выглядят как обычные строки, а JSON отформатирован.

Значения отправляются в базу как текст и приводятся Postgres к типу колонки, поэтому любой тип правится в своём обычном текстовом виде: `{periphery,usb}` для массива, `{"dpi": 1600}` для jsonb, `2026-10-18 12:00+05` для timestamptz, `new`/`paid` для enum (их подскажет автодополнение).

## Автодополнение в ячейках

`ctrl-space` в ячейке предлагает то, что подходит колонке: `NULL` (если колонка допускает), `DEFAULT` (если есть значение по умолчанию), `+` в ключе, `true`/`false` для `boolean`, значения enum (`new`, `paid`, `shipped`, `cancelled` для `orders.status`).

## Что видно до записи

Пока вы правите, zpg проверяет буфер на лету:

- на первой строке — что будет записано: `pending: 1 update, 1 insert, 1 delete; run the code action “Apply changes”`;
- изменённые ячейки и новые строки подчёркнуты (если включены semantic tokens);
- ошибки подчёркиваются сразу: неверное число ячеек, дубль ключа, правка обрезанного значения, текст в generated-колонке… — список в [справочнике](11-reference.md#ошибки-и-что-делать).

## Когда изменения уходят в базу

### `apply=manual` (по умолчанию)

`ctrl-s` только сохраняет файл, в базу ничего не уходит. Записать: `ctrl-.` → **zpg: Apply changes (1 update, 1 insert)**. Файл должен быть сохранён. Так случайно стёртая строка или опечатка не попадут в базу.

### `apply=save`

Каждое `ctrl-s` сразу записывает изменения. Удобно для быстрой правки, но **отменить записанное через `ctrl-z` нельзя**. С автосохранением Zed (`"autosave"`) используйте только `manual`.

Переключить режим: `apply=` в шапке, `ctrl-.` → **zpg: Apply changes manually / on save**, или `"apply"` в [настройках](02-connections.md#все-параметры) для вновь открываемых таблиц.

## Посмотреть SQL до записи

`ctrl-.` → **zpg: Preview SQL** откроет `<таблица>.preview.sql` с тем, что выполнится:

```sql
-- What saving would run, in one transaction.
BEGIN;
UPDATE "zpg_demo"."customers" SET "city" = CAST('Milano' AS text) WHERE "id" = CAST('7' AS bigint) AND xmin = CAST('1234' AS xid) RETURNING …;
INSERT INTO "zpg_demo"."customers" ("email", "name", "city", "note") VALUES (CAST('ivan@example.com' AS text), CAST('Иван' AS text), NULL, NULL) RETURNING …;
COMMIT;
```

## Как записывается

- Все изменения страницы — **одной транзакцией**: изменённые ячейки → `UPDATE` (только изменённые колонки), новые строки → `INSERT`, удалённые → `DELETE`.
- После успеха страница перерисовывается данными из базы: появляются новые `id`, подставленные `DEFAULT`, пересчитанные триггером значения. Внизу — `zpg: saved 1 update, 1 insert`.
- Если хоть один запрос упал (NOT NULL, FK, `CHECK`, неверный тип), транзакция откатывается и **в базу не записывается ничего**. Ошибка Postgres показывается на строке, которая её вызвала, правки остаются в файле — исправьте и примените снова.

Пример: `price = -5` в `zpg_demo.products` → внизу `zpg: nothing written, transaction rolled back: new row for relation "products" violates check constraint "products_price_check"`, а на самой строке — ошибка `not saved: …` с деталями Postgres.

## Защита от чужих изменений

Каждый `UPDATE` и `DELETE` проверяет, что строка не менялась с момента загрузки (по системной колонке `xmin`). Если её успел изменить кто-то другой, запись отменяется с ошибкой «row was changed or deleted since it was loaded; refresh to see the current data». Сделайте **Refresh** и внесите правку заново.

## Что нельзя править

- **Обрезанные значения (`…`).** zpg не знает, что вы имели в виду. Откройте [просмотр строки](07-relations.md#просмотр-строки), увеличьте `width` в шапке (`width=0` отключает обрезку) или оставьте меньше колонок через `columns=`.
- **Ключ существующей строки.** Изменение ключа — это удаление старой строки и вставка новой. Сработает, но учтите внешние ключи с `ON DELETE CASCADE`: удаление заказа удалит его позиции.
- **Generated-колонки** — только `DEFAULT`.
- **Таблицы без первичного ключа, view, materialized view, подключения `read_only`** — только чтение.
