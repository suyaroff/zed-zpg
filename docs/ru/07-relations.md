# Связи и просмотр строки

## Переход по внешнему ключу

**F12** (или `ctrl`+клик) на ячейке внешнего ключа открывает связанную таблицу, отфильтрованную до той строки, на которую он ссылается.

В `zpg_demo.orders` курсор на `customer_id` первой строки → F12:

```
# zpg v1 conn=local table=zpg_demo.customers pk=id page=1 limit=100 total=1 width=40 apply=manual where="id = '1'"
| id | email            | name         | city    | vip  | created_at                    | note |
|----|------------------|--------------|---------|------|-------------------------------|------|
| 1  | anna@example.com | Анна Петрова | Ташкент | true | 2026-10-18 01:40:44.321115+05 | NULL |
```

- Чтобы снова увидеть всю таблицу: `ctrl-.` → **zpg: Clear filter**, или удалите `where` из шапки и сохраните.
- Если в связанной таблице есть незаписанные правки, она откроется как есть, без фильтра.
- **Hover** на ячейке внешнего ключа сразу показывает строку, на которую он ссылается, — переходить не обязательно:

  ```
  customer_id bigint · not null · → zpg_demo.customers(id)

  → zpg_demo.customers (F12 opens it)
  - id: 1
  - email: anna@example.com
  - name: Анна Петрова
  - city: Ташкент
  …
  ```

Составные внешние ключи работают так же: фильтр будет по всем колонкам ключа.

## Кто ссылается на строку

Обратное направление: какие строки других таблиц ссылаются на эту.

- **Hover** на ключевой ячейке показывает внешние ключи, которые указывают на таблицу:

  ```
  id bigint · primary key · not null · has default

  ← referenced by zpg_demo.orders(customer_id)
  ```

- **`ctrl-.` на строке данных** → **zpg: Rows of zpg_demo.orders referencing this (customer_id)** открывает `zpg_demo.orders` с `where="customer_id = '1'"` — все заказы этого покупателя.

  Из заказа так же видны его позиции: на строке `zpg_demo.orders` → **Rows of zpg_demo.order_items referencing this (order_id)**.

Такие действия идут в конце меню `ctrl-.`, по одному на каждый внешний ключ, который указывает на таблицу. У популярных таблиц (например, `users`) их бывает несколько десятков.

## Просмотр строки

**F12** на ячейке первичного ключа (или `ctrl-.` → **zpg: Open row**) открывает строку вертикально — по полю на строку текста. Файл: `.zpg/local/zpg_demo.customers.rows/4.pgr`.

```
# zpg v1 row conn=local table=zpg_demo.customers key=id=4
id: 4
email: dilnoza@example.com
name: Дилноза Каримова
city: Самарканд
vip: true
created_at: 2026-10-18 01:40:44.321115+05
note: |
  Две строки:
  вторая строка
```

Для `jsonb` (`zpg_demo.products`, строка 3):

```
# zpg v1 row conn=local table=zpg_demo.products key=id=3
id: 3
sku: MN-27
title: Монитор 27"
price: 289.00
tags: {display}
attrs: |
  {
      "hz": 144,
      "size": 27,
      "panel": "IPS"
  }
active: true
```

Правила:

- Значение с переводами строк записывается блоком: `имя: |`, затем строки с отступом в два пробела. Добавляйте и удаляйте строки внутри блока как обычный текст.
- `jsonb` показывается отформатированным (`jsonb_pretty`); в базу уходит как есть, Postgres сам его разберёт.
- Однострочные значения пишутся как в таблице: `NULL`, `DEFAULT`, экранирование `\n` и т. п. `имя:` без значения — пустая строка.
- Значения не обрезаются — это способ поправить то, что в таблице показано с `…`.
- Ключевые поля менять нельзя, порядок и состав полей тоже.
- Изменённые поля подчёркиваются, на первой строке появляется `pending: 1 update`.
- Записывается по тем же правилам, что и таблица, в режиме таблицы, из которой открыта строка: при `manual` — `ctrl-.` → **zpg: Apply changes**, при `save` — `ctrl-s`. После записи страница таблицы тоже обновится, если в ней нет своих незаписанных правок.
- Hover и F12 по внешнему ключу работают и здесь, как и **Rows of … referencing this**.
- Повторный F12 на том же ключе перечитывает строку из базы. Исключение: если в `.pgr` есть незаписанные правки, он откроется как есть, правки не пропадут. Перечитать вручную: `ctrl-.` → **zpg: Refresh row (discard changes)**.
